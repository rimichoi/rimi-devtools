# chmod 검증 벡터

`src/tools/chmod/vectors.ts` 의 값이 어디서 왔는지 남긴다. 손으로 적은 값이 아니라
**실제 파일에 chmod 를 걸고 `stat(1)` 이 낸 출력**이다.

## 왜 필요한가

8진수와 `rwxr-xr-x` 를 오가는 규칙 자체는 단순하다. 조용히 틀리는 자리는 **특수
비트가 심볼릭 표기에 그려지는 방식** 하나다.

| 클래스 | 특수 비트 | 실행 권한 있음 | 실행 권한 없음 |
| --- | --- | --- | --- |
| 소유자 | setuid | `s` | **`S`** |
| 그룹 | setgid | `s` | **`S`** |
| 기타 | sticky | `t` | **`T`** |

대소문자 구분이 핵심이다. `4644` 는 `rwSr--r--` 이지 `rwsr--r--` 가 아니다 —
소문자로 적으면 "실행 권한이 있다" 는 뜻이 되어 사실과 다른 화면이 나온다.
그리고 틀려도 화면에는 여전히 그럴듯한 아홉 글자가 보인다.

그래서 규칙을 손으로 검토하는 대신 **4096개(0000-7777) 전부**를 OS 에 물어봤다.
테스트는 그 표와 구현을 양방향으로 대조한다.

## 재생성

```bash
node tools/chmod-vectors/generate.mjs > src/tools/chmod/vectors.ts
```

- macOS 의 `stat -f '%Sp'` 를 오라클로 쓴다. Linux 라면 `stat -c '%A'` 로 바꿔야 한다.
- **파일 그룹을 먼저 자기 기본 그룹으로 바꾼다.** 그러지 않으면 커널이 setgid 비트를
  조용히 떨어뜨려서 2000번대 2048개가 전부 0으로 돌아온다. 실제로 처음에 그렇게 됐다.
  생성기는 `chgrp` 를 먼저 부르고, 커널이 유지한 모드를 되읽어 하나라도 어긋나면
  던진다.

## 이 표는 테스트 전용이다

`logic.ts` 는 이 표를 **참조하지 않는다**. 참조하면 테스트가 표를 표와 비교하는
셈이 되어 아무것도 검증하지 못한다 — 이 저장소가 열 번 겪은 실수다. 구현은 비트
연산으로 직접 계산하고, 테스트만 이 표를 오라클로 읽는다.

`vectors.ts` 는 `logic.test.ts` 에서만 import 하므로 앱 번들에 들어가지 않는다.

## CI 는 chmod 를 요구하지 않는다

Jasypt · Spring 벡터와 같은 규칙이다. 생성기는 저장소에 남기되 테스트는 생성기에
의존하지 않는다. 값은 `vectors.ts` 에 박아 두고 그것만 읽는다.
